# patches/tphdr/ —— TP 头模板（122 字节，不是 128 MB）

## 这是什么

A 槽固件包的 TP 头（tphdr）占 NAND `0x4800000` 起 `0x20000` 字节，
但**真正的数据只有前 0x120 字节**，其中非零字节 **122 个**，最后一个在 `+0xdf`。
`+0xe0` 之后全是 `0x00`。

`tphdr-head.hex` 就是这前 `0x120` 字节（16 字节一行，共 18 行）。

```
+0x000  00 00 01 00 55 aa 9d d1    magic（tpl_boot_one 校验）
+0x010  41 08 00 00 41 08 00 00    load / entry = 0x41000000
+0x028  00 00 00 09                保留（原厂值，勿改）
+0x030  00 40 00 00  00 02 00 00   factory_info  0x400000  / 0x20000
+0x038  00 48 00 00  00 02 00 00   art           0x480000  / 0x20000
+0x040  00 50 00 00  00 20 00 00   config        0x500000  / 0x200000
+0x048  04 70 00 00  00 04 00 00   u-boot A      0x4700000 / 0x40000
+0x050  04 80 00 00  00 02 00 00   tphdr 自身    0x4800000 / 0x20000
+0x058  04 88 00 00  00 40 00 00   kernel        0x4880000 / 0x400000  ← 长度被重写
+0x05c                            → 0x480000（命令 --kblk）
+0x060  04 fc 00 00  00 c0 00 00   rootfs        0x4fc0000 / 0xC00000  ← 长度被重写
+0x064                            → 0xBC0000（= A_ROOTFS 真实长度）
+0x068  06 a0 00 00  01 60 00 00   rootfs_data   0x6a00000 / 0x1600000
+0x090  16 字节                      md5(u-boot 槽 0x40000)          ← 被重写
+0x0a0  16 字节                      md5(kernel‖rootfs)              ← 被重写
+0x0b0  16 字节                      保留（原厂值，勿改）
+0x0c0  "WTA301V1" + 00.. + 00 00 00 01   机型字符串
+0x0d0  16 字节                      保留（原厂值，勿改）
+0x0e0  …                            全 0
```

注意 `+0x58` / `+0x60` 存的是**地址**，长度在后面 4 字节（`+0x5c` / `+0x64`）。
原厂长度 `0x400000` / `0xC00000` 会被重写为 `0x480000` / `0xBC0000`。

`mk_op_pack.py` 只会覆盖 **4 个字段**：`+0x5c`（内核长度）、`+0x64`（rootfs 长度）、
`+0x90`（u-boot 槽 md5）、`+0xa0`（kernel‖rootfs md5）。其余逐字节保持原样。

## 为什么独立成文件

原来 `mk_op_pack.py` 的唯一输入是 **128 MB 全盘镜像**
（`work/backup/flash_full_128M.bin`），只为了从 `0x4800000` 取出这 122 字节。

后果：**别人 clone 仓库必然构建失败** ——
那个 128 MB 文件不在仓库里（也不可能在：`.gitignore` 全 `*.bin`，
而且它是整台设备的 flash 转储，含 ART 校准数据与出厂配置）。

把「122 字节的模板」和「128 MB 的设备转储」解耦之后，
仓库不再需要任何人分发全盘镜像。

## 合法性

这 122 字节是 **TP-Link 自家刷写工具生成的头部字段**（地址、长度、摘要、机型名），
不含射频校准数据、不含密钥、不含用户配置。ART 分区在 `0x480000`，
与这里无关。

`+0x90` / `+0xa0` 两段摘要是出厂固件的哈希 —— 会被 `mk_op_pack.py` 重写，
留着只是为了「模板即原件」这一属性便于逐字节核对。

## 怎么核对

```bash
# 有自己的全盘镜像时，可以直接比
dd if=flash_full_128M.bin bs=1 skip=$((0x4800000)) count=$((0x120)) 2>/dev/null \
  | xxd -p -c16 | diff - patches/tphdr/tphdr-head.hex && echo "一致"

# 或者从板子上取（root 后）
dd if=/dev/mtd13 bs=1 count=$((0x120)) 2>/dev/null | xxd -p -c16
```

`deliver/verify-repro.sh` 会校验：
文件在位、18 行 × 32 hex 字符、magic = `0000010055aa9dd1`、
`+0x48` = `0470000000040000`（u-boot A 槽）、
`+0x58` = `0488000000400000`（kernel）、
`+0x60` = `04fc000000c00000`（rootfs）、
`+0xc0` = `WTA301V1`。
