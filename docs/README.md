# docs/ —— 排查记录与证据

这里的 75 篇文档**不是教程**，是本工程做这项移植时的**过程记录**：
每一篇对应一个具体问题、当时的假设、走到死路的尝试、以及最后的决定性证据。

按 `AGENTS.md` 的规矩写的：结论分三档（**已实证** / **推断** / **未验证**），
每条都附日志路径与原始行。

## 读之前需要知道的两件事

### 1. 文档里出现的路径、IP、主机名都是**作者当时的环境**

会看到这样的东西：

```
/root/ow2512                        ← 作者的 OpenWrt 构建树
/mnt/c/Users/Sophia/...             ← 作者的 Windows 目录（经 WSL 访问）
C:\Users\null\Desktop\...           ← 作者另一台机器上的临时文件
192.168.1.175                       ← 板子在作者局域网里 DHCP 拿到的地址
192.168.1.1                         ← 上游路由器（也可能就是这块板子自己）
null@192.168.112.222                ← 作者的测试机
```

**这些不打算改。** 它们是取证记录的一部分 —— 一篇写着
「在 `192.168.1.175` 上 `telnet 2323` 拿到 uid=0」的日志，把地址换成
`<你的板子IP>` 就不再是可核对的记录了。

代码里没有这个问题：`deliver/` 下的脚本全部用环境变量覆盖路径
（`OWTREE` / `REL` / `BDFDIR` …），`tools/` 下的默认值只是方便，都能改。
`deliver/verify-repro.sh` §4/§5 会检查代码层不再出现个人绝对路径。

### 2. 编号（P1…P30、R18…R20、M12…）是**工作阶段**，不是版本号

- `P<N>-*` —— 第 N 阶段做的事（P30 = 第 30 轮，对应已上板验证的 `p30` 镜像）
- `R<N>-*` —— 第 N 轮「外部证据」检索（§0 要求：动第三方组件前先联网）
- `M<N>-*` —— 第 N 个模块的专项（M12 = ath11k 固件与 BDF）

它们之间没有严格的先后依赖，是并行推进的不同线。

## 目录约定

- `*-EXTERNAL-EVIDENCE.md` —— 联网检索的外部依据，每条带 URL 与原文摘录
  （`AGENTS.md` §0 的产物）。**外部结论 ≠ 本板结论**，这些文档里都有板级差异表。
- `*-VERIFIED.md` / `*-INCIDENT-*.md` —— 真机实证记录，附日志行。
- 其余为阶段报告。

## 不要做的事

1. **不要照着旧文档的结论直接改代码**。每条结论都标了三档，`推断` 与 `未验证`
   的不算数。要看当前状态就读代码与 `deliver/verify-repro.sh` 的输出。
2. **不要修改这里的日志原文**。发现错误就在新文档里纠正并引用旧文（本工程
   这么做过若干次，搜「自纠」）。
3. **不要把这里的路径当配置**。要配的值都在 `deliver/lib-paths.sh` 与
   `patches/bdf/README.md` 里。
