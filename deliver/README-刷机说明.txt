====================================================================
 WTA301 (TP-Link) —— OpenWrt 25.12.6 刷机说明
 版本：P28  ·  内核 6.12.112  ·  构建时间 2026-11-06
====================================================================

【这一版最大的变化：以后刷机不用再进 u-boot 了】

  以前每次刷机都要「按住 reset 上电 40 秒 → 红灯 → 浏览器 192.168.1.1」。
  原因是上游 OpenWrt 的 ipq50xx 平台脚本里根本没有这块板的分支，
  在系统里点「刷写固件」会往一个不存在的分区写，必然失败。

  P28 把这条链路补齐了。刷上 P28 之后：

    · 升级固件 → LuCI「系统 → 备份/刷写固件」上传 sysupgrade 包，点一下就完
    · 配置和已装的软件包都会保留（overlay 在另一块分区，不会被碰）
    · 只有「救砖」和「换 u-boot」才需要进 u-boot 网页

  ⚠ 但第一次（从 P26 升到 P28）仍然必须用 u-boot 网页包，
    因为分区表的改动在内核的设备树里，得刷进去才生效。
    刷完 P28 后可以验证一句：
        ssh root@192.168.1.1 'cat /sys/class/mtd/mtd5/size'
    输出 7602176 就对了（旧固件是 4194304）。

【这一版包含的调优（全部烧进固件，不需要任何 shell 调试）】

    · 5G   : 信道 161 / 80MHz / 国家码 CN / cell_density 2
    · 2.4G : 信道 11  / 20MHz / 国家码 CN / cell_density 2
    · 网卡中断负载从「全压在 CPU0」改为分散到两核（eth0 中断移到 CPU1）
    · 内核网络参数按本机实测调整（netdev_budget=1000）
    · 5G 实测 590 Mbps 平均 / 675 峰值（手机当客户端，同位置）

 二、三种刷法，按场景选
====================================================================

 【场景 1】正常刷机（第一次从旧固件升到 P28）
  1. 电脑网线接路由器 LAN 口，网卡设成自动获取 IP
  2. 路由器断电
  3. 按住 reset 键不放，插电
  4. **继续按住 40 秒**，直到指示灯变红
     （这一步最容易失败 —— 按不够 40 秒只会正常启动，进不了刷机模式）
  5. 浏览器打开 http://192.168.1.1
  6. 上传 wta301-op-25.12.6-p28.bin，等它写完（约 1-2 分钟，别断电）
  7. 自动重启，约 60 秒后 Wi-Fi 出现

 【场景 2】以后升级（已经在 P28 上）
  LuCI → 系统 → 备份/刷写固件 → 选「刷写新固件」
  上传 wta301-op-25.12.6-pXX-sysupgrade.bin → 取消勾选「保留配置」以外的选项
  （保留配置是默认开着的，保持默认即可）→ 点「刷写固件」
  写入约 10 秒，自动重启。

  命令行等价：
      scp wta301-op-25.12.6-pXX-sysupgrade.bin root@192.168.1.1:/tmp/
      ssh root@192.168.1.1 'sysupgrade -v /tmp/wta301-op-25.12.6-pXX-sysupgrade.bin'
  只检查不刷（干跑，推荐先跑一次）：
      ssh root@192.168.1.1 'sysupgrade -T /tmp/wta301-op-25.12.6-pXX-sysupgrade.bin'

 【场景 3】变砖 / 网页刷机页打不开
  A. 网页刷机页还能进  → 走场景 1
  B. 网页页进不去，但有 USB-TTL 线
       1. TTL 线接路由器串口（115200 8N1）
       2. 上电时疯狂敲 "slp" 抢 u-boot 命令行
       3. 按 flash_cmds.txt 里的命令逐条执行（电脑开 tftpd）
       4. 或直接用 rescue 目录里的稀疏包，一次擦一次写：
            nand erase 0x4800000 0x1380000
            nand write 0x44000000 0x4800000 0x1380000
  C. 两条都不行
       路由器有双系统槽（A/B）。写坏 A 槽会自动落到 B 槽（原厂固件），
       仍能开机。所以「刷坏 = 变回原厂」，不是变砖。

 【想回原厂固件】
  刷过 P28 之后可以直接在系统里刷：
      dd if=flash_full_128M.bin bs=1 skip=$((0x4880000)) count=$((0x740000)) \
         | mtd write - kernel
      dd if=flash_full_128M.bin bs=1 skip=$((0x4FC0000)) count=$((0xC00000)) \
         | mtd write - rootfs
  boot_flag 不用改（它 = 2，指向 A 槽，原厂固件就在 A 槽）。
  注意这会丢掉 overlay 里的配置，回原厂本来就该是干净状态。

 四、刷完怎么确认（可选，一条命令）
====================================================================

      ssh root@192.168.1.1 'sh -s' < verify-p28.sh

  它会逐项打印 OK / FAIL。正常应全部 OK（OK=24~30，FAIL=0）。
  想连镜像一起干跑检查：
      ssh root@192.168.1.1 'sh -s' < verify-p28.sh /tmp/wta301-op-25.12.6-p28-sysupgrade.bin

  另外 verify-p26.sh 仍然可用（检查调优项），两个都跑一遍最稳。

 五、技术细节（想深入了解再看）
====================================================================

  网页刷机写入区间：0x4800000 .. 0x5B80000
    +0x4800000  firmware 头     0x20000
    +0x4880000  内核            0x480000
    +0x4FC0000  根文件系统      0xBC0000
    另外还会重造 +0x1BC0000 的 overlay 区（27.9 MB）

  系统内升级只写两块：
    mtd5 kernel  0x4880000  声明 0x740000（P28 从 0x400000 加宽）
    mtd6 rootfs  0x4FC0000  0xC00000
  不碰 mtd12 上的 overlay（UBI 卷 wta301data），所以配置全留。

  为什么 kernel 分区要加宽：
    内核 FIT 实际是 4,280,940 B（0x41526c），比原厂分区表声明的 0x400000
    大 86,636 B。原厂 u-boot 按固件头里记录的 KERNEL_LEN 读写、不看分区表，
    所以一直没事；但系统内的 mtd 工具会检查分区大小，声明小了就拒绝写。
    0x4880000 + 0x740000 = 0x4FC0000，正好接到 rootfs 起点，无重叠。

  不在写入区间内的：
    +0x0        一级 u-boot（出厂，永不改）
    +0x4700000  二级 u-boot
    +0x6A00000  一块 22 MB 闲置分区（保留未用）

  本版预置的调优文件（全部在固件里，不在配置区）：
    /usr/sbin/net-tune                     网卡中断 + rps 看护进程
    /etc/init.d/net-tune + /etc/rc.d/S99net-tune
    /etc/sysctl.d/99-wta301-net.conf       netdev_budget=1000 等
    /etc/uci-defaults/99-wta301-net        packet steering 设置
    /etc/uci-defaults/99-wta301-wireless   无线出厂值兜底
    /lib/upgrade/platform.sh               系统内刷写支持（本版新增）
