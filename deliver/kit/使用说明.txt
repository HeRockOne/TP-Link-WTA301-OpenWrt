WTA301 一键工具
====================================================================

一台 Windows 电脑，一个目录，全部搞定。不需要装 Python。
（Windows 10 / 11 自带的 PowerShell 5.1 就够了。）


一、怎么开始
--------------------------------------------------------------------
1. 把整个目录拷到电脑上（不要只拷 .bat 或 .ps1 一个文件）
2. 双击 启动.bat
   · 它会自己申请管理员权限（要改网卡地址和防火墙，必须管理员）
   · 先跑一遍离线自检，确认文件齐全、密码学能跑
   · 问你设备 IP，直接回车是 192.168.1.1
   · 然后进菜单
3. 第一次连上会花几秒取 root，之后所有操作都复用这条连接，
   不会再重新取一次。

如果设备已经在跑 OpenWrt 且你知道 root 密码，那根本不需要取 root，
直接走菜单里对应的刷机项即可。


二、这个目录里有什么
--------------------------------------------------------------------
  启动.bat       入口。提权 -> 自检 -> 问 IP -> 进菜单
  wta301.ps1     全部逻辑（单文件，零依赖）
  使用说明.txt   本文件
  MD5SUMS.txt    每个文件的 md5，用来核对拷贝是否完整
  uboot\         u-boot kit（单独一个目录，理由见里面的 README.txt）
  images\        OpenWrt 固件包（完整包 + sysupgrade 包）
  stock\         原厂回退镜像（四个文件，刷回原厂/修回退槽用）


三、菜单各项干什么
--------------------------------------------------------------------
[1] 取 root           只在设备还是原厂时需要。取到之后什么也不改。
[2] 刷 OpenWrt        把 images\ 里的完整包写进 A 槽。
[3] 只刷 u-boot kit   把 uboot\ 里的文件写进两槽 u-boot（一级 u-boot 不动）。
[4] 刷回原厂          把 stock\ 里的原厂镜像写进 A 槽，重启就是原厂。
[5] 安全审计          只读。列出两槽状态、u-boot 状态、五条救砖出口。
[6] 整片备份          把 15 个分区全抓到本机，带 md5 清单。
[7] 修 B 槽            把原厂镜像写回 B 槽（B 槽坏了才需要）。
[8] TTL 串口刷 u-boot 只为救砖。设备连不上网时才用，115200 8N1。
[9] 分区表与风险      看物理偏移、两个槽的关系、三个已知的坑。


四、刷 u-boot 不需要 TTL（这条容易误会）
--------------------------------------------------------------------
菜单 [3] 刷 u-boot 走的是网络 —— 把 bin 上传到设备 /tmp，
再用 dd 写 mtd9（A 槽）和 mtd4（B 槽），写完回读 md5 比对。
只要设备能起来、能拿到 shell，全程不用插 TTL 线。
刷固件（[2] / [4]）同理。

TTL 线（菜单 [8]）只在一种情况下才需要：**设备完全连不上网**，
也就是根本拿不到任何 shell ——
  · getroot 失败（固件版本不同、漏洞失效、不在路由模式…）
  · 两个槽都验不过，一级 u-boot 进恢复模式
  · 分区表 / boot_flag 错乱，系统起不来

换句话说：TTL 是「没有 shell 可用」时的最后手段，不是流程里的必经一步。


五、安全边界（这几条写死在代码里，加了 -Yes 也绕不过）
--------------------------------------------------------------------
永远不写的四个分区：
  mtd0  0x0000000  一级 u-boot + SBL/QSEE/CDT   TTL 命脉
  mtd1  0x0400000  出厂信息（机型 / MAC）
  mtd2  0x0480000  射频校准（ART）
  mtd14 0x4000000  boot_flag（选槽标志）

需要显式授权才写的分区：
  0x0700000 / 0x4700000  两槽 u-boot     -> 只有 [3] 和 [8] 能写
  0x0880000 / 0x0fc0000  B 槽内核/rootfs -> 只有 [7] 能写

刷 A 槽时 B 槽一个字节都不动，反过来也一样。
一级 u-boot 有双向回退：一个槽验不过会自动去验另一个，所以单槽坏不变砖。


六、三个必须知道的坑（都是实测踩出来的）
--------------------------------------------------------------------
坑 1：同一个 mtd 编号在两个固件下指向完全不同的物理位置
      原厂固件   mtd5 = 0x0880000（B 槽内核）
      我们的     mtd5 = 0x4880000（A 槽内核）
      而且命名互为主备（这边叫 kernel，那边叫 kernel_bak）。
      所以本工具一律按【绝对偏移】反查编号，从不按名字或编号硬编码。

坑 2：备份文件的名字也会反
      stock\mtd5_kernel.bin         内容其实在 0x4880000（A 槽）
      stock\mtd10_kernel_bak.bin    内容其实在 0x0880000（B 槽）
      所以本工具只认 md5，不认文件名。自检会把对应关系打出来给你看。

坑 3：原厂固件的可写层是空的
      boot_cart2.log（我们动手之前）就报
      "jffs2 not ready yet; using ramdisk" 和 "mount /dev/mtdblock7 on /rom/overlay failed"。
      也就是说这台机器出厂就这样：/etc 的改动写进 tmpfs，重启就丢。
      这不是刷机搞坏的。


七、日志
--------------------------------------------------------------------
每次运行都会在工具目录下生成 wta301-YYYYMMDD-HHmmss.log，
里面是完整记录（包括设备那边的交互）。出问题先看这个。


八、需要什么
--------------------------------------------------------------------
· Windows 10 / 11（自带 PowerShell 5.1），管理员权限
· 网线一根：电脑接设备的 LAN1
  ── 取 root 只要这个，不需要连设备 WiFi，不需要中继模式，
     也不需要 scapy / ARP 投毒（那会把网络搞坏）
· TTL 串口线（**只在救砖时需要**，刷机刷 u-boot 都用不上）：
  USB-TTL，115200 8N1，TX/RX 交叉接，GND 必须接
  插上后在设备管理器里看是 COM 几，菜单 [8] 会问你
